## Ограничения

- Платёжный шлюз является локальным эмулятором; банковские списания и возвраты не выполняются.
- Платёж содержит сумму чаевых и банковскую комиссию: 2% для СБП, 5% для карты и SberPay. Комиссию оплачивает клиент либо она удерживается из чаевых официанта; сумма чека не участвует в расчёте.
- Приложение использует Django 4.2 и локальную БД по настройкам проекта; production deployment требует HTTPS, безопасных cookie/HSTS и production DB.
- Для подписи требуется внешний `TIP_QR_SECRET`; ключ нельзя хранить в Git или логах.

## Пользовательские сценарии

### Клиент оставляет чаевые
1. Сотрудник/владелец создаёт QR, клиент открывает ссылку.
2. Клиент выбирает цель (если есть), сумму чаевых, способ оплаты, плательщика банковской комиссии, оценку сервиса/ресторана, комплименты и комментарии.
3. Клиент отправляет платёж и подтверждает его; API возвращает `SUCCESS`, `DECLINED` или `PENDING`.

### Клиент отменяет платёж
1. До подтверждения отправляет `POST /api/v1/payments/{payment_id}/cancel` с `confirm_token`.
2. Платёж из `CREATED` становится `CANCELED`; отмена из `PENDING`/финального статуса отклоняется.

### QR устарел
1. Клиент отправляет запрос чаевых по QR с истёкшим сроком.
2. API отвечает `410 QR_EXPIRED`, платёж не создаётся.

### Сотрудник добавляет цель
1. Владелец или сотрудник создаёт цель через API целей.
2. QR показывает сумму цели и прогресс; прогресс увеличивается только после `SUCCESS`.
