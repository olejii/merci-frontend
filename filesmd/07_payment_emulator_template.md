# Механизм эмуляции платежа

## Состояния и переходы

| Состояние | Значение |
|---|---|
| `CREATED` | Запрос проверен, запись создана, результат шлюза ещё не запрошен |
| `PENDING` | Эмулятор не получил окончательный результат; разрешено повторное подтверждение |
| `SUCCESS` | Эмуляция успешна |
| `DECLINED` | Эмулятор отклонил операцию; содержит `CARD_DECLINED` |
| `CANCELED` | Клиент отменил запрос до отправки на подтверждение |

| Из | В | Условие |
|---|---|---|
| `CREATED` | `PENDING` | Подтверждение принято |
| `PENDING` | `SUCCESS` | Эмулятор вернул успешный исход |
| `PENDING` | `DECLINED` | Эмулятор вернул отказ |
| `PENDING` | `PENDING` | Эмулятор вернул таймаут; повторное подтверждение возможно |
| `CREATED` | `CANCELED` | Клиент отменил до подтверждения |
| `PENDING` | `CANCELED` | Запрещено, ответ 409 `CANCEL_NOT_ALLOWED` |
| `SUCCESS` | `CANCELED` | Запрещено; возврат средств не реализован |

## Обработка

1. Разобрать JSON, проверить сумму, метод, оценки, комментарии, цель и idempotency key; ошибка — 422.
2. Найти QR и проверить HMAC, exp, ACTIVE мерчанта и одноразовость; ошибки — `INVALID_QR`, `QR_EXPIRED`, `MERCHANT_BLOCKED`, `QR_USED`.
3. Рассчитать только `tip` и `fee` (`0` или `25.00`); `amount_total = tip + fee`.
4. Создать запись `CREATED`, отметить QR использованным атомарно и записать событие аудита.
5. Проверить idempotency key: идентичный запрос возвращает существующую запись; отличающийся запрос получает 409.
6. Подтверждение переводит `CREATED` в `PENDING`, затем эмулятор вычисляет исход; каждое изменение аудируется. Эмулятор детерминирован: повтор для того же `qr_id + nonce` возвращает тот же исход.
7. Отказ возвращает `DECLINED/CARD_DECLINED`; таймаут оставляет `PENDING/GATEWAY_TIMEOUT`; успешный исход возвращает `SUCCESS`.
8. Отмена допустима только из `CREATED`, устанавливает `CANCELED` и сохраняет аудит; отмена из `PENDING` запрещена.

## Алгоритм детерминированного эмулятора

```text
h = int(SHA256((qr_id + nonce).encode("utf-8")), 16) % 10
h ∈ [0, 7]  -> SUCCESS
h = 8       -> DECLINED / CARD_DECLINED
h = 9       -> PENDING / GATEWAY_TIMEOUT
```

При `h=9` повтор подтверждения тем же QR не меняет результат в этой демонстрационной реализации; реальный асинхронный callback/reconciliation отсутствует.

Банковская комиссия рассчитывается от суммы чаевых с округлением до копеек: 2% для `SBP`, 5% для `CARD` и `SBERPAY`. При `cover_service_fee=true` комиссию оплачивает клиент (`amount_total = tip + service_fee`, `employee_net_amount = tip`); при `false` комиссия удерживается из чаевых официанта (`amount_total = tip`, `employee_net_amount = tip - service_fee`). Процент чаевых и сумма блюда не вычисляются. Подпись QR: `HMAC-SHA256(TIP_QR_SECRET, merchant_id|employee_id|nonce|exp).hexdigest()[:16]`.

Исторический CSV содержит примеры: `p_0001`/`qr_001`, сумма чека 637.00 ₽, tip 31.85 ₽, status `SUCCESS`; `p_0003`/`qr_003`, сумма чека 911.00 ₽, tip 136.65 ₽. Старые даты и статусы CSV — снимок, не результат текущего эмулятора. Проверяемый отказ в unit-тесте задаётся nonce так, что `h=8`.

## Ошибки и повтор

| Ситуация | Код | HTTP | Повторяемо |
|---|---|---:|---|
| Неверная HMAC | `INVALID_QR` | 422 | Нет |
| QR не найден | `INVALID_QR` | 404 | Нет |
| QR истёк | `QR_EXPIRED` | 410 | Нет, нужен новый QR |
| QR уже использован | `QR_USED` | 409 | Нет, нужен новый QR |
| Мерчант не активен | `MERCHANT_BLOCKED` | 403 | После разблокировки |
| Чаевые вне диапазона | `TIP_OUT_OF_RANGE` | 422 | После исправления суммы |
| Неподдерживаемый метод | `PAYMENT_METHOD_INVALID` | 422 | После исправления метода |
| Идентичный idempotency key и payload | — | 200 | Безопасный replay, тот же payment ID |
| Тот же ключ с другим payload | `IDEMPOTENCY_CONFLICT` | 409 | Нет, новый ключ |
| Эмулятор вернул 8 | `CARD_DECLINED` | 402 | Да, новая операция/QR по правилам UX |
| Эмулятор вернул 9 | `GATEWAY_TIMEOUT` | 200, статус `PENDING` | Повтор в этой версии даст тот же детерминированный timeout |
| Отмена из `PENDING` | `CANCEL_NOT_ALLOWED` | 409 | Нет |
| Отмена из `SUCCESS` | `CANCEL_NOT_ALLOWED` | 409 | Возврат не реализован |

Таймаут не доказывает отсутствие списания у настоящего провайдера; в текущей версии внешнего провайдера нет.

## Аудит и границы эмулятора

В `AuditEvent` хранятся `event_id`, `payment_id`, `qr_id`, `action`, `from_status`, `to_status`, `amount_total`, `actor`, `at`, `details`. В эмуляторе нет банковских SDK, PAN/CVV, реальных списаний или переводов сотруднику.
