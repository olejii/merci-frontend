# Информационная безопасность

## Модель угроз

| ID | Угроза | Актив | Вероятность | Ущерб | Меры / остаточный риск |
|---|---|---|---|---|---|
| U-1 | Подделка QR | Доверие к ссылке и операция клиента | Средняя | Высокий | HMAC-SHA256 с секретом из окружения и constant-time compare; низкий при защите ключа |
| U-2 | Повторное использование QR | Деньги клиента | Средняя | Средний | TTL 24 часа, уникальный nonce, атомарный `used_at`; низкий |
| U-3 | Утечка payout-реквизитов сотрудника | Персональные/финансовые данные | Средняя | Высокий | Ввод только last4 и хранение `****NNNN`; низкий |
| U-4 | Двойной запрос/двойная операция | Деньги клиента | Средняя | Высокий | Уникальный per-merchant idempotency key и проверка соответствия payload; низкий |
| U-5 | Подмена суммы или метода клиентом | Целостность платежа | Средняя | Высокий | Серверная валидация суммы, fee, метода, рейтинга; фронтенду не доверять; средний без rate limit |
| U-6 | Отсутствие следа при разборе инцидента | Аудит/расчёты | Низкая | Высокий | `AuditEvent` на создание, подтверждение, отказ, отмену и timeout; средний до защиты журналов от изменения |

## RBAC

| Действие | Мерчант | Сотрудник | Клиент | Администратор |
|---|---|---|---|---|
| Регистрация | Да, заявка | По приглашению | Не требуется | Проверяет заявку |
| Генерация QR | Для своих сотрудников | Только себе | Нет | Да |
| Просмотр чаевых | В пределах своего заведения | Только своих | Нет | Да |
| Открытие/сканирование QR | Нет | Нет | Да | Нет |
| Оплата | Нет | Нет | Да | Нет |
| Отчёт | Только своего мерчанта | Только собственный | Нет | Любой |
| Блокировка мерчанта | Нет | Нет | Нет | Да |
| Изменение справочников | Нет | Нет | Нет | Да |

## Аудит

`AuditEvent` содержит поля:

| Поле | Тип | Пример |
|---|---|---|
| `event_id` | string | `evt_...` |
| `payment_id` | FK/string | `p_0001` |
| `qr_id` | FK/string | `qr_001` |
| `action` | string | `payment_created` |
| `from_status` | string | `CREATED` или пусто |
| `to_status` | string | `PENDING` |
| `amount_total` | decimal | `105.00` (чаевые 100 ₽ + комиссия 5%, оплаченная клиентом) |
| `actor` | enum | `client`, `system`, `merchant`, `admin` |
| `at` | datetime | ISO-8601 |
| `details` | JSON | `{"error_code":"GATEWAY_TIMEOUT"}` |

## Персональные данные и секреты

- PAN и CVV не принимаются и не хранятся: интеграции с реальными платёжными методами нет.
- Полные payout-реквизиты запрещены; допустимо только `****NNNN`.
- Email профиля валидируется, максимум 254 символа и уникален без учёта регистра; телефон уникален и хранится в E.164.
- В логах нельзя писать пароли, invite token, CSRF/session cookie, confirm token, полный реквизит или секрет.
- HMAC хранится в поле QR как подпись, но секрет HMAC хранится только в `TIP_QR_SECRET` вне репозитория.

| Секрет | Хранение | Доступ | Ротация |
|---|---|---|---|
| `DJANGO_SECRET_KEY` | Secret manager / environment | Runtime сервиса и узкий круг операторов | По процедуре инфраструктуры |
| `TIP_QR_SECRET` | Secret manager / environment | Runtime QR API | Плановая ротация с периодом перекрытия/инвалидацией старых QR |
| Пароль БД | Secret manager / environment | Runtime DB user | По политике production |

## Незакрытые меры перед production

- Rate limiting для регистрации, авторизации, выдачи QR и создания платежей отсутствует.
- Требуются HTTPS и production-конфигурация `SECURE_SSL_REDIRECT`, HSTS, secure session/CSRF cookies, `XFrameOptionsMiddleware`, `ALLOWED_HOSTS`.
- SQLite, Django Admin и детерминированный платёжный эмулятор — только для прототипа; нужны production-БД, секрет-хранилище, мониторинг и реальный PCI-совместимый провайдер. Не хранить данные карт даже при подключении провайдера.
