# Тест-сценарии T3

Проверки выполнялись Django TestCase с изолированной тестовой БД. Сумма чека и проценты из первоначального шаблона не применяются: платформа принимает конкретную сумму чаевых.

| ID | Сценарий / данные | Ожидаемый результат | Фактический результат |
|---|---|---|---|
| T3-1 | Создать QR; отправить `tip_amount=31.85`, затем подтвердить | `SUCCESS`, чаевые 31,85 ₽, сумма списания равна чаевым плюс выбранная комиссия | PASS: `test_successful_tip_payment` — ответ 201, после confirm `SUCCESS`, проверены сумма и audit events |
| T3-2 | Создать платёж для QR, для которого эмулятор даёт результат 8 | `DECLINED`, `CARD_DECLINED` | PASS: `test_declined_gateway_payment` |
| T3-3 | Изменить HMAC существующего QR | `422 INVALID_QR`, платёж не создан | PASS: `test_invalid_qr_creates_no_payment` |
| T3-4 | Повторить идентичный запрос с тем же idempotency key | Тот же `payment_id`, HTTP 200 при replay, одна запись | PASS: `test_idempotent_retry_returns_existing_payment`; иной ключ при использованном QR получает `QR_USED` |
| T3-5 | Отменить платёж в `CREATED`, затем проверить отмену из `PENDING` | Первый становится `CANCELED`; второй получает 409 `CANCEL_NOT_ALLOWED` | PASS: `test_cancel_before_confirmation_and_reject_cancel_after_pending` |

Дополнительный тест `test_expired_qr_returns_gone` подтверждает ответ `410 QR_EXPIRED`; созданный платёж при этом отсутствует. Тесты `test_payment_link_returns_qr_data_json_and_csrf_protects_payment` и `test_payment_link_requires_a_valid_qr` проверяют JSON-ответ ссылки оплаты и ошибки QR. В полном прогоне набора Django выполнен 21 тест, все прошли.

Привязка сценариев к тестам автоматизирована; фиксированные CSV-идентификаторы не используются в unit-тестах. Реальные CSV содержат исторические QR с истёкшими датами и предназначены для импорта/демонстрации, а не для оплаты.

## Импорт исходных данных

Тесты импорта проверяют dry-run без записей, идемпотентность, сохранение локальных правок, отказ при некорректном внешнем ключе и дублирующемся nonce. Прогон полного набора CSV в режиме `--dry-run` показал 20 merchants, 60 employees, 100 QR и 100 payments к созданию; транзакция откатила все записи.
